# 答辩清单 · 舍得（AI 断舍离决策助手）

> 上台前照此过一遍，5 分钟确认演示不会出意外。

## 一、演示前 30 分钟

- [ ] 清库重置演示数据：删除 `backend/data/database.sqlite` 和 `backend/Photos/` 内容（避免旧数据和物品上限干扰）
- [ ] 双击 `一键启动.bat`，确认窗口出现 `Uvicorn running on http://0.0.0.0:8000`，**窗口全程不关**
- [ ] 浏览器打开 `http://localhost:8000/`（网页演示版，方式1同源，无 CORS 问题）
- [ ] 微信开发者工具打开 `miniprogram/`，AppID 用测试号，「详情 → 本地设置」勾上**不校验合法域名**
- [ ] 手机/电脑连同一网络（如需真机预览小程序）

## 二、演示动线（网页版，约 3 分钟）

1. **看板**：三态统计（待决策 / 观察中 / 已决定）+ 到期红点 → 点「拍照决策一件物品」
2. **拍照识物**：选一张物品照片 → AI 识别出名称/分类/描述 → 「确认，开始决策」
   - 无 AI key 时自动走演示识别，**不会卡**
3. **四问**：使用频率 / 重新购买 / 可替代 / 情感，全部作答 → 「提交，生成建议」
4. **建议页**：结论 chip + 总分 /100 + 理由 + 六维条形图
   - 强调口径：**分数越高越该留**；占用空间分越高 = 越省空间
   - 强调原则：**AI 只给建议，最终决定权在用户**
5. **做决定**：点「观察 30 天」→ 自动跳观察箱
6. **观察箱**：倒计时、到期红点、「我用到了」计数（≥3 次提示可直接留下）、留下 / 处理
7. **处理建议**：出售（含估价区间 + 推荐平台）/ 转赠 / 回收 / 丢弃四渠道 → 「复制文案」→「标记已处理」

## 三、可能被问到的问题

| 问题 | 一句话回答 |
|---|---|
| 和收纳/库存 App 有什么区别？ | 不做库存管理，只做「要不要留」的决策；物品只有 pending / observing / resolved 三态 |
| AI 出错怎么办？ | AI 只出建议和理由，六个最终决定按钮都在用户手里；无 key 时全链路规则降级，不 500 |
| 为什么有 30 天观察箱？ | 断舍离最大的阻力是「万一以后用得上」，观察箱用时间换确定性，到期再决定 |
| 六维分怎么来的？ | 固定四问 → 规则映射 + 权重加权；有 key 时 GLM-4 打分，无 key 规则兜底，口径一致 |
| 数据存哪？ | 本地 SQLite（`backend/data/database.sqlite`），图片在 `backend/Photos/` |
| 小程序和网页版什么关系？ | 小程序是产品载体，网页版只读复用同一套后端接口，供答辩现场浏览器演示 |

## 四、兜底预案

- **AI 超时/报错**：后端自动降级规则打分，理由里会注明「AI 不可用，已用规则打分」——可以直接当成设计点讲
- **网络问题**：网页版与后端同机同源，断外网也能演示（仅 AI 调用需要外网，且会降级）
- **端口被占**：`停止服务.bat` 后重新双击 `一键启动.bat`
- **数据异常**：删掉 `backend/data/database.sqlite` 重启，自动重建空库并建演示账号

## 五、仓库结构（讲解用）

```
├─ 一键启动.bat / 停止服务.bat
├─ README.md / 使用说明.md
├─ backend/      FastAPI + SQLite（v0~v5 接口，含决策层）
├─ miniprogram/  微信小程序（产品载体）
├─ web/          网页演示版（纯静态，挂后端 / 下）
└─ docs/         交接文档与答辩材料
```
