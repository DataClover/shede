# 方案 A · 《舍得》网页演示版（精准规格）

> 定位：**小程序是产品载体（不动），网页版是只读复用后端、仅演示“决策流”的独立 Web 前端**，供答辩现场用浏览器一键打开。
> 约束：不改任何业务/后端逻辑代码；后端接口全部复用，**零新增接口**。

## 0. 术语（先对齐）

* **产品载体** = 现有微信小程序，保持现状，不删不改。
* **网页演示版** = 新增的轻量 Web 前端（Vue3 / 原生 HTML 皆可），只实现决策流，不实现收纳/搜索/设置。
* **后端** = `backend/`（FastAPI，`localhost:8000`），复用现有 `v0/v3/v5` 接口。

## 1. 两个必须知道的前置事实

1. **身份是写死的**：演示 openid = `demouser00000000000000000000`（`demouser` + 20 个 `0`，28 位）。
2. **必须先建用户**：所有物品/决策接口内部都按 openid 查 `user_id`，用户不存在会 500。所以网页版**首次进入必须先调一次** `GET /v0/home/info?openid=demouser...`，由后端 `create_user` 建号；后续不再重复。

## 2. 跨源与托管（方案 A 唯一要你拍板的点）

后端 CORS 生产配置（`launch.py` L73–83）只放行 3 个域名，**不含 localhost**，浏览器直接跨源请求会被拦。两种落地方式：

* **方式 1（推荐，演示最顺）**：后端加 2 行“配置级”改动（非业务逻辑）——CORS `allow_origins` 增加 `http://localhost:5173`（或开发期用 `*`），并把网页静态产物挂到 `/`（`StaticFiles(directory="web_dist", html=True)`）。效果：双击 `一键启动.bat` → 浏览器打开 `http://localhost:8000/` 即用。
* **方式 2（零后端改动）**：前端用 Vite dev server，`server.proxy` 把 `/v0 /v3 /v4 /v5 /auth /Photos` 全部代理到 `http://localhost:8000`，实现同源、无 CORS。代价：答辩要同时开“后端 + 前端 dev”两个进程，且走 `http://localhost:5173`。

> 若你坚持“一行后端都不碰”，选方式 2；若接受“2 行配置、零业务改动”，选方式 1（我更推荐，演示更稳）。

## 3. 页面清单（决策流 7 个视图）

| #  | 视图     | 职责                              | 关键接口                                 |
| :- | :----- | :------------------------------ | :----------------------------------- |
| 1  | 看板（首页） | 三态计数 + 到期卡片 + 「拍照决策」主按钮 + 待决策列表 | overview、observe/list?status=pending |
| 2  | 拍照识物   | 选图上传 → 展示识别结果 → 确认/编辑 → 存为物品    | image/upload、item/add                |
| 3  | 四问     | 渲染 4 问 → 提交分析                   | decision/questions、decision/analyze  |
| 4  | 建议     | 六维 + 分数 + 理由 + 四选一              | decision/choose                      |
| 5  | 观察箱    | 倒计时 + 到期红点 + “我用到了” + 留下/处理     | observe/list、observe/use、observe/due |
| 6  | 处理建议   | 出售/转赠/回收/丢弃 四渠道文案               | dispose/suggest、dispose/plan         |
| 7  | 决策详情   | 照片 + AI 结论 + 六维 + 当前状态          | decision/item                        |

## 4. 接口契约（精确到入参/出参，实现按此对接）

**身份**

* `openid` 恒为 `demouser00000000000000000000`。
* `GET /v0/home/info?openid={openid}` → `status=new_user|existing_user`（建号用）。

**看板**

* `GET /v5/observe/overview?openid=` → `data.{pending, observing, resolved, observed_kept, observed_sold, due_count, observe_days, total}`。
* `GET /v5/observe/list?openid=&status=pending` → `data.{count, due_count, items[]}`；`items[]` 含 `item_id,title,category,image_filename,ai_verdict,ai_score,days_left,expired`。

**拍照识物（两段）**

1. `POST /v3/image/upload`（`multipart/form-data`：`openid` + `image` 文件）→ `data.{image_filename, analysis_result:{name,description,category,tags}, ai_raw_content}`。
2. `POST /v3/item/add`（JSON）：
   ```json
   {"openid":"...","box_id":null,"bag_id":null,"title":"...","description":"...","category":"...","image_filename":"<上一步 image_filename>","tags":["..."]}
   ```
   → `data.item_info.item_id`（后续决策都用它）。
   **铁律**：`box_id` 与 `bag_id` 必须**同时省略**（后端要求“同空或同有”，独立物品 = 同空）。

**四问与分析**

* `GET /v5/decision/questions` → `data.questions[]`（`key,title,options[{value,label}]`）、`data.dim_labels`。
* `POST /v5/decision/analyze`（JSON）：
  ```json
  {"openid":"...","item_id":1,"usage_answer":"recent|month|long|never","rebuy_answer":"yes|unsure|no","replace_answer":"none|has|broken","emotion_answer":"high|mid|low"}
  ```
  → `data.{dims, dim_labels, score, verdict(keep|observe|dispose), reason, advice, source}`。

**四选一**

* `POST /v5/decision/choose`（JSON）：
  ```json
  {"openid":"...","item_id":1,"decision":"keep|observe|sell|gift|recycle|discard"}
  ```
  → `data.{decision, status, status_text, observe_until, observe_days, dispose_channel}`。

**观察箱**

* `GET /v5/observe/list?openid=&status=observing`。
* `POST /v5/observe/use`（`{"openid":"...","item_id":1}`）→ `data.{observe_used_count, days_left, hint}`（≥3 次 hint 会建议直接留下）。
* `GET /v5/observe/due?openid=`。

**处理建议**

* `POST /v5/dispose/suggest`（`{"openid":"...","item_id":1,"channel":"sell|gift|recycle|discard|""}`）→ `data.suggest.{channel,title_text,body_text,price_range?,platforms,tips,source}`。
* `GET /v5/dispose/plan?openid=&item_id=`。

## 5. 三条关键顺序（实现易踩坑处）

1. **图片**：`image/upload` 存到 `Photos/temp`；`item/add` 传入 `image_filename` 后，后端把图移到 `Photos/<user_id>/` 并写回相对路径。网页端展示图片的 URL = `{baseUrl}Photos/{image_filename}`（例如 `http://localhost:8000/Photos/1/1699.jpg`）。
2. **建议页→处理**：用户在建议页点“出售/转赠/处理”时，**先**调 `decision/choose` 落 `decision`（sell/gift/recycle/discard），**再**跳 `dispose/suggest` 生成文案。
3. **观察箱→处理**：观察中物品的 `decision` 还是 `observe`，直接调 `dispose/suggest` 会 400。必须先 `decision/choose` 改成 dispose 类，再进处理建议。

## 6. 明确不做（边界）

* 不做储物箱/收纳袋、不做搜索、不做设置/about/privacy/help。
* 不做真实微信登录（固定演示 openid）。
* 不改后端业务逻辑、不加新接口。
* 不改小程序任何文件。

## 7. 验收标准

1. `一键启动` 后浏览器打开即用（方式 1）或两个进程能起（方式 2），无 CORS 报错。
2. 全链路：拍照识物 → 4 问 → 六维建议+理由 → 四选一 →（观察箱 30 天 / 处理建议）。
3. 观察箱能倒计时、到期红点、“我用到了”计数、留下/处理闭环。
4. 处理建议四渠道（出售含估价区间）均可出可复制文案。
5. 演示模式下全程不 500、不卡 AI（AI 识别/分析自动降级为模拟/规则）。
6. 答辩前清一次库（删 `database.sqlite` + `Photos` 内容），避免旧数据或 30 件上限干扰。
