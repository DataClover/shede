> 课程定位是“AI 通识进阶”，老师更关心 **AI 是什么、为什么用 AI、怎么保证可信**，而不是页面好不好看。

## 二、演示动线（网页版，约 3 分钟）

1. **看板**：三态统计（待决策 / 观察中 / 已决定）+ 到期红点 → 点「拍照决策一件物品」
2. **拍照识物**：选一张物品照片 → AI 识别出名称/分类/描述 → 「确认，开始决策」
   - 无 AI key 时自动走演示识别，**不会卡**
3. **四问**：使用频率 / 重新购买 / 可替代 / 情感，全部作答 → 「提交，生成建议」
4. **建议页**：结论 chip + 总分 /100 + 理由 + 六维条形图
   - 强调口径：**分数越高越该留**；占用空间分越高 = 越省空间
   - 强调原则：**AI 只给建议，最终决定权在用户**
5. **做决定**：点「观察 30 天」→ 自动跳观察箱
6. **观察箱**：倒计时、到期红点、「我用到了」计数（≥3 次提示可直接留下）、留下 / 处理
7. **处理建议**：出售（含估价区间 + 推荐平台）/ 转赠 / 回收 / 丢弃四渠道 → 「复制文案」→「标记已处理」

## 四、兜底预案

- **AI 超时/报错**：后端自动降级规则打分，理由里会注明「AI 不可用，已用规则打分」——可以直接当成设计点讲
- **网络问题**：网页版与后端同机同源，断外网也能演示（仅 AI 调用需要外网，且会降级）
- **端口被占**：`停止服务.bat` 后重新双击 `一键启动.bat`
- **数据异常**：删掉 `backend/data/database.sqlite` 重启，自动重建空库并建演示账号

# 答辩 Q&A

> 每一条都是「老师可能怎么问 → 你怎么答（要点）」。**不要背稿**，记“关键事实 + 一句话逻辑”，现场用自己的话讲。

## 1. 项目定位：你们到底做了什么？

**问**：这个项目和普通收纳 App 有什么区别？

**答要点**：
- 底座是开源收纳工具，**我们的增量是“决策层”**：拍照识物 → 4 问 → 六维打分 → 四选一 → 30 天观察箱 / 处理建议。
- 不做库存管理，只做「要不要留」的决策；物品不搞收纳层级，**只有三态：待决策 / 观察中 / 已决定（pending / observing / resolved）**。
- 一句话：**收纳只是记录“你有什么”，断舍离是帮你想清楚“该不该留”。**
- 用户痛点：想扔又舍不得、纠结（PPT 调研数据支撑）。

## 2. AI 具体做了哪几件事？模型怎么选的？

**问**：这个项目里 AI 用在哪？用的什么模型？

**答要点**（三层 AI，各一句话）：
1. **识物**：`glm-4v-flash`（视觉模型）看照片，输出物品名称/描述/分类/标签。
2. **决策分析**：`glm-4-flash`（文本模型）读 4 问答案，输出六维分数 + 保留建议 + 理由文案。
3. **处理文案**：AI 生成出售/转赠/回收/丢弃的建议文案。
- 选智谱：国产、有免费额度、中文好、课程作业可零成本演示。
- **兜底**：三个 AI 点都有规则降级，无 key 或 AI 失败时走规则（`source=rule`），演示永不卡死。

## 3. 为什么这个场景非要大模型？用规则表格不行吗？（最关键）

**问**：判断扔不扔，写个 if-else 不就行了，为什么要用大模型？

**答要点**（讲 AI 的“不可替代性”，这是进阶课的核心）：
- **规则只能覆盖你提前写好的情况**，但物品和理由是开放的：“外婆送的坏掉的手表”——这需要**理解语义 + 情感判断**，规则表写不完。
- AI 在这的四层价值：**识别**（照片里是什么）、**理解**（用户回答背后的含义）、**判断**（综合六维权衡）、**生成**（给出有人味、有理由的建议）。
- 我们同时保留规则兜底，正好体现“AI 负责开放场景、规则负责保底”的工程思路。

## 4. 六维分数是 AI 算的吗？可解释吗？

**问**：那个“建议分数”怎么来的？可信吗？

**答要点**：
- 六维：使用频率(0.25)、是否重复(0.20)、实际需求(0.15)、重新购买(0.15)、占用空间(0.10)、情感价值(0.15)，**分数越高越该留**。
- 口径一句话：**固定 4 问 → 规则映射 + 权重加权**；有 key 时 GLM-4 打分，无 key 规则兜底，两者口径一致。
- 分数来源在接口里用 `source` 字段标注：`ai`（大模型）或 `rule`（规则兜底）。
- 阈值：≥65 留、40–64 观察、<40 处理；**观察箱 30 天**是给用户反悔的缓冲。
- 可解释性：不只看分数，**每条建议都带一句“理由”**，用户能看懂为什么。

## 5. 提示词工程怎么做的？怎么保证 AI 稳定输出？

**问**：让大模型输出结构化结果，你们怎么保证稳定？

**答要点**：
- 要求模型**按固定 JSON 格式**输出（六维分数、verdict、reason），后端解析失败即回退规则。
- 控制 `temperature`、`max_tokens`，避免乱答。
- 关键：**AI 输出只影响“建议质量”，不破坏主流程**——AI 挂了，流程照走，只是建议变保守。

## 6. AI 识别错 / 幻觉怎么办？

**问**：AI 把东西认错了、或给了不靠谱建议，怎么办？

**答要点**：
- 识别结果**用户可确认/编辑**，不直接入库。
- 决策只是**建议**，最终四选一由用户拍板。
- 所有 AI 点有规则兜底 + 演示模式降级，不会把错误结果强加给用户。

## 7. 为什么最终决定权给用户？这算什么设计？

**问**：你们让 AI 建议、用户决定，是技术不行还是刻意设计？

**答要点**（刻意设计，且是亮点）：
- **AI 不替人做价值判断**，断舍离的本质是“人的价值观”，AI 只做分析。
- 最终决定永远是用户点选：前端 **4 个主选项**（留下 / 观察 / 出售或转赠 / 处理），落到系统是 6 种结果，但**按钮始终在用户手里**。
- 30 天观察箱 = 给“舍不得”一个缓冲，而不是逼你马上扔。
- 这是负责任的 AI 产品观：**AI 增强人，不替代人的决定权**。

## 8. 工程与部署：怎么保证能跑起来？

**问**：演示能保证稳定吗？换个电脑能不能跑？

**答要点**：
- 后端 FastAPI + SQLite；**网页版是答辩载体，小程序是产品载体**，网页版只读复用同一套后端接口（不改后端）。
- **一键启动**：双击 `一键启动.bat` → 自动建虚拟环境、装依赖、自检数据库、起服务、自动打开浏览器；含端口占用/缺 Python/网页未托管等明确报错。
- 演示模式不依赖真实微信账号和智谱 key，换电脑也能跑。

## 9. 数据与隐私怎么处理？

**问**：用户照片、数据存哪？安全吗？

**答要点**：
- 全部**本地**：SQLite 数据库 + 本地 Photos 目录，不上传第三方服务器。
- 演示模式用固定 openid，不碰真实微信账号。
- 课程项目，仅本地演示。

## 10. 有哪些局限？下一步？

**问**：说说这个项目的不足和后续计划？

**答要点**（诚实 + 有计划）：
- 六维里“是否重复”目前用“有替代”近似、占用空间暂中性——**口径已在文档标注，是 MVP 取舍**。
- AI 依赖外部 key，演示模式是降级结果。
- 下一步：真实微信登录、真机拍照、订阅提醒、调研数据补全（对应 README 版本表 v1.0）。

## 11. 代码来源合规吗？

**问**：前端是你们自己写的吗？

**答要点**（主动坦白，别被追问才说）：
- 底座复用开源项目（GitHub 链接，无 LICENSE，默认保留权利），**仅课程作业使用，不商用不分发**。
- 决策层（4 问/六维/四选一/观察箱/处理建议）是我们自己的增量。
